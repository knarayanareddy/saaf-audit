PDCA Cycle — What happens when?

SAAF sessions follow a Plan-Do-Check-Act loop across hackathons. Today covers Plan & Do. The other phases happen at your organisation between sessions.

Plan & Do — hackathon day
  • Plan: design your agent, skill, or workflow
  • Do: build a working prototype in your track
Check & Act — between sessions
  • Check: test at your organisation, collect findings
  • Act: share results & improvements at next hackathon

Getting Started

How to contribute a plan to the SAAF repository

Do I need Git?

Just browsing? You can read all plans on GitHub without any local setup — click any plan card on the Tracks page to open it directly.

Want to contribute a plan? Follow the six steps below. If you get stuck, ask Mathijs or Eduward — or open a GitHub Discussion.

1

Fork & clone the repository

The easiest way is with the gh CLI (GitHub CLI). This creates your own copy and clones it locally in one step.

gh repo fork SAAF-Project/SAAF-Project --clone
cd SAAF-Project

Don't have gh? cli.github.com — or use the Fork button on GitHub and clone manually.

2

Create a branch

Use your name and a short description. Keep it lowercase with hyphens.

git checkout -b your-name/plan-your-slug
3

Write your plan

Copy the template into the Hackathon #4 folder and fill it in. Claude Code can help — open the repo in Claude Code and ask it to help fill in each section.

cp docs/plans/plan-template.md \
  plans/hackathon-4/firstname-lastname-slug.md

File naming: lowercase, hyphens, pseudonym allowed. Example: jan-bakker-vendor-risk-agent.md

Not sure what to write? Browse plans/overview.md for inspiration — or pick a gap from gap-analysis.md.

4

Reference & claim other plans

Link to related plans using relative paths in your markdown. This shows how your work builds on or extends the community portfolio.

See also: [RAG KB](../hackathon-3/saaf-rag-knowledge-base.md)

To claim a plan (signal "I'm building this at my org"), add your name to the Claimed By field in Section 1 of that plan's metadata. This prevents others from duplicating your effort.

5

Update the PDCA status

Section 11 of the template has a PDCA table. Mark each phase as you go: Not started → In progress → Complete. This shows the community how far along your work is.

6

Commit, push & open a Pull Request

git add plans/hackathon-4/firstname-lastname-slug.md
git commit -m "plan: firstname-lastname-slug"
git push origin your-name/plan-your-slug
gh pr create --title "Plan: your slug" --base main

Once merged, your plan appears in the harness automatically after the data is regenerated.
