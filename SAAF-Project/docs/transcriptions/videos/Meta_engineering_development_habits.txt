One of the best ways to get better at using Cloud Code is to always be meta-engineering your development systems no matter what task you're actually working on. What I mean by that is that as you're using Cloud Code, you're developing certain habits with how you interact with the system. Maybe you just send it once, send it's prompts and go back and forth within 100 times to accomplish a task. Or maybe you give it a 2000 line prompt and Cloud Code completes the entire project autonomously. These are different habits and you should be always critical of the way that you're interacting with the tool. A great way to get insights into how to better your habits with Cloud Code as a beginner is to ask Cloud Code itself. It has a built-in tool that allows it to understand all the mechanisms and features of Cloud Code itself so it can help you actually use itself better as a tool. For instance, working in an existing project, you can ask Cloud Code, what are some Cloud Code skills or Cloud Code slash commands that I could create in this project to make my development workflow a bit more efficient here. If you want to get even more meta about it, you can ask Cloud Code to ask you questions about your work and your business and your development workflow and ask you what are some global systems that you could install in your global.cloud folder like hooks or skills or slash commands that will help you on a daily basis no matter what you're working on.
