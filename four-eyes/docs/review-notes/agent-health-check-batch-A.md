## Patterns across the batch

- Fail-open defaults are the main behaviour risk. Three-way-match says MATCH on a doctored or blank invoice, hallucination scoring says LOW with real red flags, and threewaysecurity releases payments with no human. Audit tools should default to "needs review" when unsure.
- Human review is mostly a sentence, not a gate. Only Audit-criteria (on No-Go) asks for a human decision in code. RCM-Builder states it well in agent.yaml but the output has no approval field for the next agent to check.
- SAAF hygiene is thin. No repo has a licence, only 1 of 13 has agent.yaml, 5 have no AUDIT-CRITERIA.md, and 9 have no unit tests. Of those with tests, only RCM-Builder and hallucination pass cleanly.
- Secrets are handled with .env files, with no hard-coded real keys found. The exception is Finding-analysis, which serves the server key to the browser. Track-4 and Team-HighTable docs point to setup steps or files that do not exist or are missing.
- Most dependencies are unpinned (>=), and the two pinned repos fail differently: Track-4's old pandas pin does not install on Python 3.14. No lock files anywhere.

## What I could not do

- Finding-analysis and Track-4: install failed (long Windows path, and no Python 3.14 wheel for pandas 2.2.3). Both are web servers needing an API key, so they were not run.
- Audit-Work-Program, hallucination CLI, judging live run: need an API key, not run (no real model calls by design).
- Team-HighTable: not installed (torch download, TeamMate tenant and keys needed). APM-Writer: skeleton, nothing to install or run.
- three-way-match has no tests. I wrote a small probe script (in my session scratchpad, outside the repos) to run its matcher on its own sample files and three edge cases.
- No web servers were started. No deep code review: about 2 minutes per repo.
