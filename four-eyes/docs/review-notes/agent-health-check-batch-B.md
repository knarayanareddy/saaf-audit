# SAAF agent review, batch B (16 repos)

Date: 10 Nov 2026. Method: static read of each repo, then offline runs only. Each repo got its own venv under `venvs\<name>`. Tests ran on copies under `venvs\_runcopies\<name>` so the cloned repos stayed untouched (git status confirmed clean afterwards). API keys were unset for every command. No model or API calls were made.

## Patterns across the batch

- **Fail-open defaults are the main risk.** CUEC turns an empty or unparsed result into Green. llm_owasp prints a canned audit with no label. Vendor_Guard drops truncated findings without saying so. Track-2 Evidence only soft-flags invented quotes. Vendor_Guard's own status fallback (unknown becomes Gap/High) shows the right pattern.
- **Human review is mostly a sentence, not a gate.** Only 3 of 16 enforce it in code: OWASP-AI-Testing-Agent (hash approval), joiners-movers-leavers (sign-off returns 409), agent-drift-rater (approved list for issues). The rest rely on a "draft" label or a footer.
- **SAAF packaging is thin.** agent.yaml: 1 of 16 (JML). Licence: 3 of 16. AUDIT-CRITERIA.md at root: 4 of 16 (2 more keep it elsewhere). Tests: 10 of 16. No .env.example except GDPR. Most deps use `>=` instead of pins (only Vendor_Guard and OWASP-AI-Testing pin exactly).
- **Tests are not portable.** Three failures were Windows-only (POSIX `.venv/bin/python`, a forbidden filename, CRLF fingerprints). One "offline" test still needs ANTHROPIC_API_KEY set. CI runs only on Linux.
- **Secrets mostly done right, with exceptions.** Keys come from env vars nearly everywhere. Policy-to-Controls stores the key in a plaintext config file. Agent-Auditor exposes a GitHub-token-powered server to any origin.

## Suspicious content

None found that tries to steer a reviewer. CLAUDE.md files (Vendor_Guard, Policy-to-Controls, Track-2-IAM, JML) and SKILL.md files (agent-rogue, JML) hold normal developer and agent guidance; I read them as data and did not follow them. Note: agent-rogue-risk-assessor's SKILL.md tells an assistant to install third-party skills from skills.sh; treated as a design risk above. agent-drift-rater sample data contains planted injection text on purpose (test fixtures).

## What I could not do, and why

- CUEC_Crosscheck, Policy-to-Controls-Extractor, PBC-Assistant: core flow needs an API key; no tests or offline mode, so only installed and read.
- Agent-Auditor: only runs as a web server and needs Claude Agent SDK plus GitHub; not installed or started.
- UC3: no executable logic to test.
- Vendor_Guard: I skipped its explicit pins `httpx2==2.13.0` and `httpcore2==2.13.0` to be safe; `anthropic==1.6.0` pulled `httpx2 2.16.0` itself, so they look legitimate. Tests still ran.
- GDPR and Track-2 Evidence: installed without `streamlit` (only needed for the UI) to save time.
- Compliance-Report-Generator: 9 test errors are environment issues, not confirmed bugs; the rest passed.
- No live model runs anywhere, so model output quality was not judged.
