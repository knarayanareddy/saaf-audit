# Auditability Model

This project makes the agent workflow visible by writing a structured audit trail for each execution.

## Audit Events

Each event in `audit_trail.ndjson` contains:

- `event_id`: ordered event number.
- `timestamp_utc`: UTC timestamp.
- `run_id`: run identifier supplied by the user or generated by the CLI.
- `step`: workflow step name.
- `action`: plain-language action performed.
- `inputs`: relevant input metadata, including file hashes.
- `outputs`: counts, decisions or artifact paths.
- `decision`: rule logic and thresholds used.
- `previous_hash`: hash from the prior event.
- `event_hash`: SHA-256 hash of the canonical event payload.

## Why Hash Chaining

The hash chain does not prevent edits by itself, but it makes edits detectable. If an older event changes, all later hashes no longer match their recorded predecessors.

## Human Approval

Reports are draft by default. Set `EXEC_SUMMARY_REQUIRE_HUMAN_APPROVAL=false` only when another approval mechanism exists. The generated reports include a validation checklist and approval status.

## Source Traceability

Findings include source file and row references for related risks and controls. The manifest records hashes of generated artifacts so reviewers can confirm which files belonged to the run.
