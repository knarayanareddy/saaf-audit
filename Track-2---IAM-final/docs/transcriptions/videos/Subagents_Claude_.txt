You're probably using Cloud Code subagents wrong, so here is how to use them correctly. If you're still using subagents to delegate different roles or personas to your subagents, like Frontend Engineer or Backend Engineer, you're missing a new key mental model involving skills and subagents together that takes over this functionality. Skills and subagents are two distinct features of Cloud Code that can work really nicely together, but it's important to understand the actual purpose of each feature independently. The main purpose of subagents is not to assign a specific role or persona, but actually to segment a new context window away from your main agent to not pollute the context window of your main agent. The main purpose of skills is to provide the information to specialize in agent to perform a specific task like Frontend Engineering or Backend Engineering. Because skills can be chained together, storing the personas and identity of different agents that you want to have working in your codebase in skills is much more customizable than storing them in individual custom subagent files. This way you can deploy general subagents directed at specific skill folders to specialize them to a given task.
