I've been using Cloud Code for over a year now, and let me show you how I set up my dot-cloud folder to get the best results. First, Agents. These are your specialist AI workers. I've got four of them. For example, if I need to find something in the codebase, I use a researcher agent. It digs through the entire repo and can find things hidden in any nook or corner of the codebase. Next, commands. These are your custom slash commands. Basically reusable prompts that you write once and use forever. For instance, if I want to deploy something, I just run slash deploy in Cloud and it executes all the instructions inside my deploy command. Next, hooks. These are deterministic rules that Cloud must always follow. For example, I have a block-protected-files.sh hook. If Cloud ever tries to modify anything on my protected files list, the hook immediately blocks it. No exceptions. Then there are rules. This is where I split my Cloud.md into domain-specific files so it doesn't become huge and messy. Backend.md covers API patterns and error handling. Cloud automatically loads whichever rules are relevant, so everything stays clean, modular, and fast. Next, skills. These are behavior guides that Cloud automatically invokes when it detects the right context. For example, I have a commit push skill that defines how I want commit structured. Skills are probabilistic. Cloud decides when to use them based on what it's doing. Then at the root, Cloud.md. This is basically the brain of the project. It contains the architecture, conventions, what not to touch, how to build the project, and how to test it. Cloud reads this at the start of every session and finally settings.jsom. This is where hooks are wired up and permissions are defined. What Cloud is allowed to run, what it can't run, and when. And if you're wondering what environment I'm running this in, I'm using DevSwarm. It lets you run multiple branches in parallel, each with its own isolated IDE, so you can experiment, build features, and review code without branches interfering with each other. You can try it yourself at devswarm.ai.
