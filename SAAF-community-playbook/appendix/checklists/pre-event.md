# Pre-Event Checklist

Copy this checklist for each session. Tick each item as it's done.

---

## Six Weeks Before

- [ ] Date, venue, and host organisation confirmed in writing.
- [ ] **Maximum headcount agreed with venue and sponsor.** This is
      the cap — the working constraint, not an aspiration to exceed.
- [ ] Theme or focus area decided (optional but useful).
- [ ] Save-the-date sent to the chapter mailing list.
- [ ] **Calendar invitation sent** to the chapter distribution list.
      Cap stated in the invitation description. Accept / decline on
      the invitation is the RSVP — no separate reconfirmation step.
- [ ] Sign-up link for non-list members provided (sign-up form
      collects: name, organisation, role preference, dietary needs,
      photo consent, accessibility needs — stored in the operator's
      contact list, not re-collected per session).
- [ ] Keynote speaker invited (see [speaker-brief.md](../templates/speaker-brief.md)).
- [ ] Plan submission deadline announced (typically 2 weeks before
      the session).
- [ ] Operator-in-charge confirmed for the day.
- [ ] Recap writer named.
- [ ] Track leads named (if multi-track).

## Four Weeks Before

- [ ] Operator checks accepts vs cap. If approaching cap, **waiting
      list activated** — new sign-ups told they are on the waitlist.
- [ ] Catering provider quoted; menu drafted.
- [ ] Initial plan list shared with the chapter — both submitted and
      in-progress.
- [ ] Venue walkthrough scheduled with the operator (date set, even
      if the walkthrough itself happens later).
- [ ] If hybrid: streaming setup tested at the venue.

## Two Weeks Before

- [ ] Plan submission deadline reached. Captain reviews submitted
      plans.
- [ ] Day's tracks decided based on plan distribution.
- [ ] Speaker brief sent to keynote speaker.
- [ ] AV requirements confirmed with venue.
- [ ] Any cross-organisation logistics resolved (parking access,
      security gates, etc.).

## One Week Before

- [ ] **Tentative responses followed up individually** by the
      operator. One short personal email per tentative, with a stated
      deadline and the waiting-list framing.
- [ ] **No-responses treated as decline** after the deadline. Removed
      from headcount.
- [ ] **Waitlist promoted** for any spots that have opened up — new
      calendar invitations sent to the next people in order.
- [ ] Catering numbers locked: accepts + (tentative-yes × 0.5)
      + 10% buffer.
- [ ] Dietary needs aggregated from the operator's contact list and
      sent to caterer.
- [ ] Final plan list circulated with sessions and tracks.
- [ ] Wifi credentials confirmed with the venue.
- [ ] Print materials prepared:
  - [ ] Table signs (track + plan numbers)
  - [ ] Welcome / agenda card on each table
  - [ ] Manifesto on the back of table signs
  - [ ] Wifi password sign for each table
  - [ ] "Do not photograph" stickers
  - [ ] Dietary labels for catering
- [ ] Speaker has confirmed attendance.
- [ ] Logistics email sent to all confirmed attendees: address, time,
      what to bring, who to contact.

## Day Before

- [ ] Final decline check: any last-minute declines promoted from
      waitlist if possible; final attendee list refreshed.
- [ ] Venue walkthrough with operator:
  - [ ] Wifi works in every corner of the room.
  - [ ] Outlets confirmed; extension strips placed.
  - [ ] AV / demo screen tested with the operator's laptop.
  - [ ] Quiet room / retreat space identified and signposted.
  - [ ] Bathrooms located.
  - [ ] Catering setup location confirmed.
- [ ] Operator's bag packed:
  - [ ] Multi-socket extension strips (one per table minimum)
  - [ ] HDMI / USB-C / DisplayPort adapters
  - [ ] Wired mouse, wired keyboard
  - [ ] Laser pointer / clicker
  - [ ] Gaffer tape
  - [ ] First-aid kit
  - [ ] Pens, Post-its, sharpies
  - [ ] Spare phone charger
  - [ ] Printed materials (above)
  - [ ] Venue contact phone numbers
- [ ] Final attendee list shared with the door / registration
      volunteer.
- [ ] Speaker reminded of arrival time and slot.
- [ ] Captain's running notes from previous session re-read.
- [ ] An early night for the captain.

---

## A Note On Skipping Items

This checklist is comprehensive because the cost of any individual
miss is high. If a session is small (e.g. 20 people), some items
collapse: one operator does multiple roles, no need for tracks.
That's fine. Don't skip items because you assume "we'll figure it
out on the day." The day is too short for figuring out.

If you find yourself skipping more than 20% of the items, either
the session is too small to need this checklist (use a simpler
internal version) or you're under-resourced and should defer the
session.
