# Running Hackathons

The build-day playbook. Used by both internal and regional chapters.

A SAAF hackathon is the visible part of the chapter — the place where
plans turn into working agents, new champions self-identify, and the
community's energy is renewed. Everything else in this playbook
exists to make these days work.

This section is the longest because the day itself has many moving
parts. Read it once end-to-end before your first hackathon. Use the
checklists in [../appendix/checklists/](../appendix/checklists/) to
operate it.

## The minimum thing to know

If you only read one page in this section, read
[format-and-agenda.md](format-and-agenda.md).

If you only read two, add
[venue-logistics-and-comfort.md](venue-logistics-and-comfort.md).
The most common reason sessions feel bad is not the agenda; it is
the wifi, the temperature, or the lunch.

## Before your first hackathon

You should already have:

- A founding team in place
  ([internal](../internal-chapter/identifying-champions.md) /
  [regional](../regional-chapter/founding-team-and-partners.md)).
- A charter and a manifesto adoption.
- An alignment session done (regional) or a session-zero dry run
  (internal).
- At least four plans submitted by participants.
- A venue confirmed, a date confirmed, a host organisation confirmed.

If any of those are missing, the hackathon is premature. Fix the
upstream issue first.
